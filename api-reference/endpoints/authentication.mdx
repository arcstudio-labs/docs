---
title: "Authentication Endpoints — Issue and Revoke API Tokens"
sidebarTitle: "Auth Tokens"
description: "Issue and revoke short-lived bearer tokens using your API key. All requests to protected endpoints must include a valid access token."
---

The authentication endpoints let you exchange your long-lived API key for a short-lived bearer token and revoke that token when it is no longer needed. Every call to a protected resource requires you to pass the bearer token in the `Authorization` header as `Bearer <access_token>`. Tokens expire after their configured TTL, so your application should handle `401 Unauthorized` responses and re-issue a token when needed.

---

## POST /v1/auth/token

Exchange your API key for a bearer token. The response includes the token string, its expiry timestamp, and the token type.

### Request parameters

<ParamField body="api_key" type="string" required>
  Your secret API key. You can find this value in your dashboard under **Settings → API Keys**. Keep it private and never expose it in client-side code.
</ParamField>

<ParamField body="expires_in" type="integer">
  Lifetime of the issued token, in seconds. Defaults to `3600` (one hour). The maximum accepted value is `86400` (24 hours). Pass a smaller value if your use case requires shorter-lived sessions.
</ParamField>

### Example request

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api.example.com/v1/auth/token \
  --header 'Content-Type: application/json' \
  --data '{
    "api_key": "sk_live_your_api_key_here",
    "expires_in": 3600
  }'
```

```python Python
import requests

response = requests.post(
    "https://api.example.com/v1/auth/token",
    json={
        "api_key": "sk_live_your_api_key_here",
        "expires_in": 3600,
    },
)
token_data = response.json()
print(token_data["access_token"])
```

```javascript Node.js
const response = await fetch("https://api.example.com/v1/auth/token", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    api_key: "sk_live_your_api_key_here",
    expires_in: 3600,
  }),
});

const { access_token } = await response.json();
```

</CodeGroup>

### Response fields

<ResponseField name="access_token" type="string">
  The bearer token to include in the `Authorization` header of subsequent requests. Treat this value with the same care as your API key.
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 timestamp indicating when the token expires, e.g. `"2024-09-15T14:00:00Z"`. After this time the token is invalid and you must request a new one.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"Bearer"`. Prepend this value to `access_token` when constructing the `Authorization` header.
</ResponseField>

### Example response

```json 200 OK
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c3JfMDEiLCJleHAiOjE3MjY0MDY0MDB9.signature",
  "expires_at": "2024-09-15T14:00:00Z",
  "token_type": "Bearer"
}
```

## DELETE /v1/auth/token

Revoke the bearer token supplied in the `Authorization` header. Use this endpoint when a user logs out or when you rotate credentials. After revocation the token is immediately invalid — any in-flight requests that include it will receive a `401 Unauthorized` response.

### Request parameters

<ParamField header="Authorization" type="string" required>
  The bearer token to revoke, formatted as `Bearer <access_token>`. This must be the same token you received from `POST /v1/auth/token`.
</ParamField>

### Example request

<CodeGroup>

```bash cURL
curl --request DELETE \
  --url https://api.example.com/v1/auth/token \
  --header 'Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...'
```

```python Python
import requests

requests.delete(
    "https://api.example.com/v1/auth/token",
    headers={"Authorization": "Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."},
)
# 204 No Content — no response body
```

```javascript Node.js
await fetch("https://api.example.com/v1/auth/token", {
  method: "DELETE",
  headers: {
    Authorization: "Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  },
});
// 204 No Content — no response body
```

</CodeGroup>

### Response

A successful revocation returns **`204 No Content`** with an empty body. If the token is already expired or was never valid, the endpoint still returns `204` so that revocation calls are safe to retry.

---

<Warning>
  **Never store bearer tokens in plain text or client-accessible storage** such as `localStorage`, source code, or unencrypted config files. Use environment variables or a secrets manager on the server side. Treat a compromised token the same way you would a compromised password — revoke it immediately and issue a new one.
</Warning>
