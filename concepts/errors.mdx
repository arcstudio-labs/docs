When a request cannot be completed, the API returns a structured error response instead of a success envelope. Every error has a machine-readable code, a human-readable message, and optional details that pinpoint exactly what went wrong. Building error handling around this structure makes your integration resilient from day one.

## Error Response Structure

All error responses use the same JSON envelope. The top-level `error` object contains everything you need to understand and respond to the failure.

```json
{
  "error": {
    "code": "validation_error",
    "message": "The request body contains invalid fields.",
    "details": [
      {
        "field": "name",
        "issue": "This field is required."
      },
      {
        "field": "type",
        "issue": "Allowed values are 'standard' or 'premium'."
      }
    ]
  },
  "meta": {
    "request_id": "req_2c9d4e8f1a",
    "timestamp": "2024-07-20T09:05:12Z"
  }
}
```

## Error Object Fields

<ResponseField name="error" type="object" required>
  The top-level container for all error information. Present on every non-2xx response.

  <Expandable title="error fields">
    <ResponseField name="error.code" type="string" required>
      A stable, machine-readable identifier for the error type. Use this value in your code when branching on error type — it will never change between API versions.
    </ResponseField>

    <ResponseField name="error.message" type="string" required>
      A plain-English description of what went wrong, suitable for logging. Do not display this directly to end users in production.
    </ResponseField>

    <ResponseField name="error.details" type="array">
      An optional array of objects providing field-level context for validation errors. Each object contains a `field` name and an `issue` description. Present only when `code` is `validation_error` or `bad_request`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error Code Reference

Use the `error.code` value to drive your error-handling logic. The table below covers every code the API may return.

| HTTP Status | Error Code | Meaning | What to do |
|---|---|---|---|
| `400` | `bad_request` | The request is malformed, missing required fields, or uses an unsupported parameter | Inspect `error.details` and fix the request before retrying |
| `401` | `unauthorized` | No API key was provided, or the key is invalid or expired | Check your `Authorization` header and regenerate the key if needed |
| `403` | `forbidden` | The authenticated key does not have permission to perform this action | Check the key's assigned scopes or contact your account administrator |
| `404` | `not_found` | The resource identified by the URL does not exist | Verify the resource ID in the path; it may have been deleted |
| `409` | `conflict` | The request conflicts with the current state of a resource (e.g. duplicate record) | Retrieve the existing resource first and reconcile before retrying |
| `422` | `validation_error` | The request body was parseable JSON but failed semantic validation | Inspect `error.details` for the specific fields and issues |
| `429` | `rate_limit_exceeded` | You have sent too many requests in a short period | Wait for the duration in the `Retry-After` header before retrying |
| `500` | `internal_error` | An unexpected error occurred on the API's side | Retry with exponential backoff; open a support ticket if it persists |
| `503` | `service_unavailable` | The API is temporarily offline for maintenance or due to high load | Check the status page and retry after the `Retry-After` interval |

## Handling Errors in Code

The examples below show how to handle API errors gracefully. Branch on `error.code` for recoverable errors and surface the `request_id` in your logs for all failures.

<CodeGroup>

```python Python
import httpx
import time

def create_resource(api_key: str, payload: dict) -> dict:
    url = "https://api.example.com/v1/resources"
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    }

    try:
        response = httpx.post(url, json=payload, headers=headers)
        body = response.json()

        if response.is_success:
            return body["data"]

        error = body.get("error", {})
        code = error.get("code")
        request_id = body.get("meta", {}).get("request_id", "unknown")

        print(f"[request_id={request_id}] API error: {error.get('message')}")

        if code == "validation_error":
            for detail in error.get("details", []):
                print(f"  Field '{detail['field']}': {detail['issue']}")
            raise ValueError("Fix validation errors and retry.")

        elif code == "rate_limit_exceeded":
            retry_after = int(response.headers.get("Retry-After", 5))
            print(f"Rate limited. Retrying in {retry_after}s...")
            time.sleep(retry_after)
            return create_resource(api_key, payload)  # single retry

        elif code == "unauthorized":
            raise PermissionError("Invalid or expired API key.")

        else:
            raise RuntimeError(f"Unhandled API error: {code}")

    except httpx.RequestError as exc:
        raise ConnectionError(f"Network error: {exc}") from exc
```

```javascript Node.js
async function createResource(apiKey, payload) {
  const url = "https://api.example.com/v1/resources";

  try {
    const response = await fetch(url, {
      method: "POST",
      headers: {
        Authorization: `Bearer ${apiKey}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify(payload),
    });

    const body = await response.json();

    if (response.ok) {
      return body.data;
    }

    const { code, message, details } = body.error ?? {};
    const requestId = body.meta?.request_id ?? "unknown";

    console.error(`[request_id=${requestId}] API error: ${message}`);

    switch (code) {
      case "validation_error":
        details?.forEach(({ field, issue }) => {
          console.error(`  Field '${field}': ${issue}`);
        });
        throw new Error("Fix validation errors and retry.");

      case "rate_limit_exceeded": {
        const retryAfter = parseInt(response.headers.get("Retry-After") ?? "5", 10);
        console.warn(`Rate limited. Retrying in ${retryAfter}s...`);
        await new Promise((resolve) => setTimeout(resolve, retryAfter * 1000));
        return createResource(apiKey, payload); // single retry
      }

      case "unauthorized":
        throw new Error("Invalid or expired API key.");

      default:
        throw new Error(`Unhandled API error: ${code}`);
    }
  } catch (err) {
    if (err instanceof TypeError) {
      throw new Error(`Network error: ${err.message}`);
    }
    throw err;
  }
}
```

</CodeGroup>

<Tip>
  Every error response includes a `meta.request_id` field. Log this value alongside the error in your system. When you contact support, sharing the `request_id` lets the team locate your specific request in the API logs and diagnose the root cause in minutes rather than hours.
</Tip>
