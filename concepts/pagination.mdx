When a list endpoint returns more results than fit in a single response, the API uses cursor-based pagination to let you walk through the full data set page by page. Unlike offset-based pagination, cursors stay accurate even when records are added or removed between requests — you never miss an item or see a duplicate.

## How Cursor-Based Pagination Works

Each response from a list endpoint includes pagination metadata alongside the results. If more pages exist, the response provides a `next_cursor` value. You send that cursor as a query parameter on your next request to fetch the following page. When `has_more` is `false`, you have reached the last page.

```
First request  →  GET /v1/resources?limit=20
Second request →  GET /v1/resources?limit=20&cursor=<next_cursor from page 1>
Third request  →  GET /v1/resources?limit=20&cursor=<next_cursor from page 2>
...and so on until has_more is false
```

## Query Parameters

<ParamField query="limit" type="integer" default={20}>
  The maximum number of results to return in a single page. Accepts any integer between `1` and `100`. Defaults to `20` if omitted. Requesting more than `100` returns a `400 bad_request` error.
</ParamField>

<ParamField query="cursor" type="string">
  An opaque pagination cursor returned by the previous response as `next_cursor`. Omit this parameter to start from the beginning of the list. Pass the exact value returned by the API — do not modify or decode it.
</ParamField>

## Response Pagination Fields

List endpoints extend the `meta` object in the response envelope with the following pagination fields:

<ResponseField name="meta.next_cursor" type="string | null">
  An opaque cursor string pointing to the start of the next page. Pass this value as the `cursor` query parameter on your next request. This field is `null` when you are on the last page.
</ResponseField>

<ResponseField name="meta.has_more" type="boolean" required>
  `true` if additional pages exist beyond the current one, `false` if this is the last page. Use this field as the condition in your pagination loop.
</ResponseField>

<ResponseField name="meta.total_count" type="integer">
  The total number of records matching the query across all pages. Useful for rendering a count or progress indicator in your UI. This field may be omitted on endpoints where an exact count is not available.
</ResponseField>

## Pagination Example

**First request — no cursor:**

```bash
curl --request GET \
  --url "https://api.example.com/v1/resources?limit=20" \
  --header "Authorization: Bearer sk_live_abc123"
```

**First response:**

```json
{
  "data": [
    { "id": "res_001", "name": "Resource One", "type": "standard" },
    { "id": "res_002", "name": "Resource Two", "type": "premium" }
  ],
  "meta": {
    "request_id": "req_1a2b3c4d5e",
    "timestamp": "2024-07-20T11:00:00Z",
    "next_cursor": "cur_eyJpZCI6InJlc18wMjAiLCJkaXIiOiJuZXh0In0",
    "has_more": true,
    "total_count": 87
  }
}
```

**Second request — pass `next_cursor` as `cursor`:**

```bash
curl --request GET \
  --url "https://api.example.com/v1/resources?limit=20&cursor=cur_eyJpZCI6InJlc18wMjAiLCJkaXIiOiJuZXh0In0" \
  --header "Authorization: Bearer sk_live_abc123"
```

**Last page response — `has_more` is false:**

```json
{
  "data": [
    { "id": "res_085", "name": "Resource Eighty-Five", "type": "standard" },
    { "id": "res_086", "name": "Resource Eighty-Six", "type": "premium" }
  ],
  "meta": {
    "request_id": "req_9f8e7d6c5b",
    "timestamp": "2024-07-20T11:00:04Z",
    "next_cursor": null,
    "has_more": false,
    "total_count": 87
  }
}
```

## Looping Through All Pages

The examples below fetch every record from a paginated list endpoint and collect the results.

<CodeGroup>

```python Python
import httpx

def fetch_all_resources(api_key: str) -> list:
    url = "https://api.example.com/v1/resources"
    headers = {"Authorization": f"Bearer {api_key}"}
    all_resources = []
    cursor = None

    while True:
        params = {"limit": 100}
        if cursor:
            params["cursor"] = cursor

        response = httpx.get(url, headers=headers, params=params)
        response.raise_for_status()
        body = response.json()

        all_resources.extend(body["data"])

        meta = body["meta"]
        if not meta["has_more"]:
            break

        cursor = meta["next_cursor"]

    print(f"Fetched {len(all_resources)} resources in total.")
    return all_resources
```

```javascript Node.js
async function fetchAllResources(apiKey) {
  const baseUrl = "https://api.example.com/v1/resources";
  const headers = { Authorization: `Bearer ${apiKey}` };
  const allResources = [];
  let cursor = null;

  do {
    const params = new URLSearchParams({ limit: "100" });
    if (cursor) params.set("cursor", cursor);

    const response = await fetch(`${baseUrl}?${params}`, { headers });

    if (!response.ok) {
      const body = await response.json();
      throw new Error(`API error: ${body.error?.message ?? response.statusText}`);
    }

    const body = await response.json();
    allResources.push(...body.data);

    cursor = body.meta.has_more ? body.meta.next_cursor : null;
  } while (cursor !== null);

  console.log(`Fetched ${allResources.length} resources in total.`);
  return allResources;
}
```

</CodeGroup>

<Note>
  Cursors are opaque, encoded strings managed entirely by the API. Never attempt to decode, parse, or construct a cursor manually — the internal format may change without notice. Always use the exact `next_cursor` string returned in the response.
</Note>
