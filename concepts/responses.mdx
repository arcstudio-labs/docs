Every response the API returns uses a consistent JSON envelope, regardless of the endpoint you called. Understanding this structure lets you write response-handling code once and reuse it across your entire integration. The body always contains a `data` field with the requested resource and a `meta` field with request context.

## Response Format

All responses — success and error alike — are returned as JSON. The `Content-Type` response header is always set to `application/json; charset=utf-8`.

A successful response wraps the result in a predictable envelope:

```json
{
  "data": {
    "id": "res_01J3K9XYZ",
    "name": "My Resource",
    "description": "A sample resource",
    "type": "standard",
    "created_at": "2024-07-15T10:32:00Z"
  },
  "meta": {
    "request_id": "req_8f4a2c1d7b",
    "timestamp": "2024-07-15T10:32:01Z"
  }
}
```

## Response Fields

<ResponseField name="data" type="object | array" required>
  The primary payload of the response. For single-resource endpoints this is an object. For list endpoints this is an array of objects. The shape of `data` varies by endpoint and is documented on each endpoint's reference page.
</ResponseField>

<ResponseField name="meta" type="object" required>
  Metadata about the request itself. Always present on every successful response.

  <Expandable title="meta fields">
    <ResponseField name="meta.request_id" type="string" required>
      A unique identifier for this specific request. Include this value when contacting support to help diagnose issues quickly.
    </ResponseField>

    <ResponseField name="meta.timestamp" type="string" required>
      The ISO 8601 UTC timestamp recording when the API processed the request, for example `"2024-07-15T10:32:01Z"`.
    </ResponseField>
  </Expandable>
</ResponseField>

## HTTP Status Codes

The API uses standard HTTP status codes to communicate the outcome of every request at a glance, before you inspect the body.

| Status Code | Name | When you'll see it |
|---|---|---|
| `200` | OK | The request succeeded and the response body contains the result |
| `201` | Created | A new resource was successfully created (`POST` requests) |
| `204` | No Content | The request succeeded but there is no body to return (e.g. `DELETE`) |
| `400` | Bad Request | The request was malformed or missing required parameters |
| `401` | Unauthorized | Your API key is missing, invalid, or expired |
| `403` | Forbidden | Your API key is valid but lacks permission for this action |
| `404` | Not Found | The requested resource does not exist |
| `429` | Too Many Requests | You have exceeded your rate limit — slow down and retry |
| `500` | Internal Server Error | Something went wrong on the API's side; try again shortly |

## Full Success Response Example

The following shows a complete response for a `GET /v1/resources/res_01J3K9XYZ` request:

```json
{
  "data": {
    "id": "res_01J3K9XYZ",
    "name": "My Resource",
    "description": "A sample resource",
    "type": "standard",
    "created_at": "2024-07-15T10:32:00Z",
    "updated_at": "2024-07-20T08:14:33Z"
  },
  "meta": {
    "request_id": "req_8f4a2c1d7b",
    "timestamp": "2024-07-20T08:14:34Z"
  }
}
```

<Note>
  List endpoints extend the `meta` object with pagination fields such as `next_cursor`, `has_more`, and `total_count`. See the [Pagination](/concepts/pagination) guide for the full structure.
</Note>
