Every request you send to the API must follow a consistent structure: the correct base URL, the right headers, and a well-formed body or query string. Getting this right upfront saves you from the most common integration errors before you write a single line of business logic.

## Base URL

All API endpoints share a single base URL. Append the resource path to this root for every request you make.

```
https://api.example.com/v1
```

For example, to reach the `/resources` endpoint:

```
https://api.example.com/v1/resources
```

## Required Headers

Every request must include the following HTTP headers. Requests missing either header will be rejected.

| Header | Value | Purpose |
|---|---|---|
| `Content-Type` | `application/json` | Tells the API to interpret the request body as JSON |
| `Authorization` | `Bearer <your_api_key>` | Authenticates your request using your API key |

<Note>
  Always use HTTPS when making requests. The API rejects all plain HTTP connections to protect your credentials and payload data in transit.
</Note>

## HTTP Methods

The API follows REST conventions. Each HTTP method carries a specific semantic meaning — use the right one for the operation you intend.

| Method | Description |
|---|---|
| `GET` | Retrieve a resource or a list of resources without modifying anything |
| `POST` | Create a new resource |
| `PUT` | Replace an existing resource in its entirety |
| `DELETE` | Permanently remove a resource |

## Request Body

For `POST` and `PUT` requests, send your payload as a JSON object in the request body. Always pair this with the `Content-Type: application/json` header.

The example below creates a new resource by sending a JSON body:

```bash
curl --request POST \
  --url https://api.example.com/v1/resources \
  --header "Content-Type: application/json" \
  --header "Authorization: Bearer sk_live_abc123" \
  --data '{
    "name": "My Resource",
    "description": "A sample resource",
    "type": "standard"
  }'
```

## Query Parameters

For `GET` requests, pass filtering, sorting, and pagination options as URL query parameters. Multiple parameters are joined with `&`.

The example below fetches a page of resources using `limit` and a pagination `cursor`:

```bash
curl --request GET \
  --url "https://api.example.com/v1/resources?limit=25" \
  --header "Authorization: Bearer sk_live_abc123"
```

Common query parameters you'll encounter across endpoints:

| Parameter | Type | Description |
|---|---|---|
| `limit` | integer | Maximum number of results to return per page |
| `cursor` | string | Opaque pagination cursor returned by the previous response |
| `sort` | string | Field name to sort results by |
| `order` | string | Sort direction — `asc` or `desc` |
